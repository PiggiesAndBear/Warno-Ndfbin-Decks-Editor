# Warno Ndfbin Decks Editor

**Play Any Unit In Any Mod.**

直接编辑 WARNO **将军模式（Army General）**牌组二进制文件（`Deck.ndfbin`）的桌面工具。
选定一个 mod，沿 师 Div → 营 Bn → 连 Co → 排 Pl 逐层下去，改掉一个营实际带什么装备 ——
**不需要改 mod 的工程源，也不需要重新构建。**

[English README](README.md) · [完整使用教程（面向无编程基础用户）](doc/使用教程.md)

## 为什么做这个

牌组数据存在编译后的二进制里。想改一件装备，常规流程是：改 mod 的 NDF 源文件 →
在 ModGen 里重新构建整个 mod → 重新部署 → 启动游戏 → 看看成了没有。
为了回答一句"这个营换成 T-80 会怎样"而走完整套流程，是不合理的。

这个工具直接读写那个二进制文件。

## 能做什么

| | |
|---|---|
| **改件数** | 4 辆改成 6 辆，该营后面的槽位排布自动重排 |
| **换装备** | 从 mod 已有的装备里选，也可以造一个它还没有的组合 |
| **插入 / 删除条目** | 往一个排里加一条装备，或者删掉一条 |
| **批量替换** | 把某件装备 —— 或**把好几种一起并成一种** —— 在 排 / 连 / 营 / 师 / **整个国家** 范围内换掉，动手前先显示会影响多少 |
| **变体** | 给一条装备换运输载具，或指定它的经验等级 |
| **筛选** | 国家 → 师 → 营，三级都可直接打字搜索 |
| **界面语言** | 简体中文 / English，即时切换 —— 不重启，也不会丢未保存的改动 |

安全性不是事后补的：

* **每次保存前先校验整份文件**。结构有问题就拒绝写入，文件一个字节都不动。
* **覆盖原文件时自动写 `.bak`** 放在旁边。
* **编辑以"条目"为单位，不是"槽位"** —— 所以不可能产生"改了一半"的坏状态
  （原因见下面[槽位模型](#槽位模型)）。

## 不能做什么

* 不能改 师 / 营 / 连 / 排 这些层级结构本身，只能改排里面装的东西。
* 不能改名（那属于本地化数据）。
* 不能改单位数值和武器参数（在别的文件里）。
* **不能跨 Mod 引用装备** —— 见[下面这条规则](#为什么不能跨-mod)。

## 安装

**从 [Releases](../../releases) 页面下载 EXE** 直接运行。Windows 会提示"发布者未知"：
这个二进制没有代码签名，SmartScreen 没有东西可以核对。点 `更多信息` → `仍要运行`。

**或者从源码运行**（需要 Python 3.10 以上）：

```bat
py -3 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python main.py
```

编辑器会自动在两个位置找 mod：

| 位置 | 是什么 |
|---|---|
| `Saved Games\EugenSystems\WARNO\mod\<名字>\` | 本机构建并部署的 mod |
| `<steamapps>\workshop\content\1611600\<id>\` | Steam 创意工坊订阅的 mod |

Steam 库的位置是**解析 `libraryfolders.vdf`** 得来的，不是靠猜，所以装在第二个硬盘上也能找到。
如果还是找不到（比如解压出来的文件夹、U 盘、另一个 Windows 账户），用 **打开 mod 文件夹**
按钮手动指定 —— 它接受任意目录。

## 快速上手

1. 选一个 mod。
2. 选国家，再选师；或者直接在师输入框里打字筛选。
3. 在左边的树里找到那个排。
4. 点右边表格里的一行（一行 = 一条装备）。
5. 按底部的按钮：**改件数** / **换装备** / **插入条目** / **删除条目**。
   双击一行可以直接跳到换装备。
6. **保存**。重启游戏确认。

完整的图文流程、每个对话框的说明、以及故障处理：
[`doc/使用教程.md`](doc/使用教程.md)。

## 实现要点

### 容器

`.ndfbin` 是一个 `EUG0`/`CNDF` 容器：分节表（`CLAS`、`PROP`、`STRG`、`EXPR`、`TRAN`、
`CHNK`、`TOPO`、`IMPR`、`OBJE`）+ zstandard 压缩的对象图 + 一张记录字符串路径的引入表。

`ndfbin_decks/core/cndf_codec.py` 无损地解码和重新编码。自检断言：对每一个给它过的文件，
**解码→编码必须逐字节相同**。这条性质是其他一切的前提 —— 如果连"原样重写"都会改掉一个字节，
那么任何编辑都不可信。

要引用一个还不在引入表里的路径，就得让那张表增长，`IMPR` 和 `TRAN` 在那里被重建。

### 槽位模型

这是唯一一个值得先弄懂的概念，也是本项目最严重那个 bug 的来源。

牌组存的不是"一个槽位一件装备"，而是**条目（entry）**；一个条目占着一串**连续的**槽位，
这一串必须是同一种装备：

```
连Co0 / 排Pl0 / 第1条   声明 3 件  ->  占槽位 0, 1, 2
连Co0 / 排Pl0 / 第2条   声明 2 件  ->  占槽位 3, 4
连Co0 / 排Pl1 / 第1条   声明 1 件  ->  占槽位 5
```

早期版本允许"一次改一个槽位"。在真实文件上，这产生了
`[T72_CMD_SOV, BM27, BM27]` —— 一个 3 槽的条目里混了两种装备，**非法**。
更糟的是，下次编辑会把该条目塌陷到它的第一个槽位，**静默删掉**另外两件。

所以：

* **编辑以条目为单位。** 整个槽池由每条装备自己的数据重新发射出来，
  于是"改了一半的条目"**根本无法表示**，而不是"被拒绝"。
* **校验器把混合条目报为硬错误**；重排器会**拒绝**重排它，而不是猜用户想要哪一种。
* **改一件数会连带重排该营后面所有条目**，因为槽位是连续排布的 ——
  这不是副作用，这就是不变式本身。

### 将军模式 vs PvP

一个 `Deck.ndfbin` 里同时装着将军模式和遭遇战/PvP 两套牌组。在某个参考文件上实测：
将军模式引用 2690 个 pack 对象，PvP 引用 2483 个，两个集合**零重叠**。
它们是互不兼容的两套结构，混用会让游戏出错。

所以可选项的判据是"**将军模式牌组有没有用它**"，而不是"这个 pack 在不在文件里"。
那个看起来更简单的替代判据 ——"它有没有定义经验等级？"—— 试过并被否决了：
它会**误杀 311 个将军模式合法使用的 pack**，因为不写经验等级正是"继承师的经验"的合法写法。

### 为什么不能跨 Mod

如果将军模式牌组引用了一个当前加载的 mod 没有定义的单位，游戏**不会报错**，
它会渲染成一个空单位。这种失败是静默的，从游戏里的表现几乎无法反推原因。

所以选择器里的"已有装备"列表只包含**正在编辑的这份文件**里的 pack，
手输的名字也要先在本 mod 的定义文件里查得到才会被接受。
用来定位一个 pack 的类型是 `(单位, 运输载具, 经验等级, 编号)`；
不存在的组合会追加一个新的 pack 对象 —— 这就是"造一个 mod 还没有的组合"如何实现，
同时又始终待在本 mod 的范围内。

### 装备定义从哪来

只从"文件引用过什么"建的清单会漏掉大部分游戏内容。真正的来源，按权威性排列：

| 来源 | 形态 |
|---|---|
| `<WARNO>/Mods/ModData/base.zip` | UniteDescriptor.ndf —— 原版基线，约 2898 个单位 |
| `<mod>/GameData/.../UniteDescriptor.ndf` | mod 的工程源，只有本机 mod 有 |
| `<mod>/Gen/NDF/GFX/Unit.ndfbin` | 编译产物 —— 创意工坊 mod 的唯一形态 |

`base.zip` 是 ModGen 自己那份，会跟着游戏补丁刷新，所以它比 mod 自带的旧快照更可信。
读一个 `Unit.ndfbin` 原本要 2.0 秒（56223 个对象）；而答案只在导出表里，
所以 `cndf_codec.read_exports()` 只走那一步 —— **0.028 秒**，且已验证与完整解码结果逐条相等。

```
ndfbin_decks/
  paths.py                  文件在哪：包内 vs 源码目录
  core/
    cndf_codec.py           .ndfbin 容器：解码 / 编码 / 增长引入表
    cndf_layout.py          分节表（TOPO/CHNK）遍历
    deckmodel.py            牌组模型：牌组、连、排、条目
    validator.py            W1-W4 不变式，每次保存前运行
    differ.py               两份文件之间改了什么
  io/
    modlocator.py           发现 mod：本机、创意工坊、任意目录
    agfilter.py             将军模式 vs PvP 的判定

    divisions.py            师标签 -> 国家（RDA 就是东德）

    tradic.py               .dic 字典读取
  edit/
    equip.py                pack 池，以及按条目换装
    quantity.py             重排器：唯一产出槽位排布的地方
    structure.py            插入 / 删除条目
    bulk.py                 按范围批量替换，带影响面预估
  app/
    session.py              一个已打开文件及其绑定的编辑器
    gui.py                  主窗口
    swap_dialog.py          装备选择 / 组合构造
    replace_dialog.py       批量替换
    catalog.py              可选装备目录

```

## 测试

```bat
.venv\Scripts\python -m tests.test_model
.venv\Scripts\python -m ndfbin_decks.selfcheck
```

每个测试最后打印一行 `PASS` / `FAIL`。测试跑在**真实的 WARNO 文件**上，
所以需要装了游戏、并且部署了这几个 mod：

| Mod | 用途 |
|---|---|
| `Test` | 主要数据集 |
| `WarnoAGF_berlin_1989` | 一个真实存在混合条目缺陷的 mod，用作回归用例 |
| `Northern Thunder`（创意工坊 `3816950018`） | 存在时追加第三个数据集 |

**没有任何路径是写死的**：位置由编辑器自己用的那个 `modlocator` 发现出来。
缺少数据的测试会打印 `SKIP — …` 并返回 0，而不是抛异常 ——
"没装游戏"应该表现为跳过，而不是"这个项目坏了"。

`tests/test_release.py` 守住发布的几条不变式：版本号只有一处来源、
图标格式是 PyInstaller 能接受的、窗口标题就是任务栏悬停显示的那句、
以及构建脚本不可能删掉已发布的二进制。

## 构建发布版

```bat
py -3 -m venv .venv-build
.venv-build\Scripts\pip install -r requirements.txt -r requirements-build.txt
.venv-build\Scripts\python build_exe.py        # -> dist_<版本>/Warno Ndfbin Decks Editor v<版本>.exe
.venv-build\Scripts\python verify_exe.py       # 无头启动、断言、杀进程
```

构建、验证、发布刻意分成三步。构建只写 `build_<ver>/` 和 `dist_<ver>/`，
**绝不碰 `dist/`** —— 所以一次失败的构建不会毁掉上一个可用版本。
`verify_exe.py` 在一个临时目录里启动候选包，断言它起来了、整个模块图都解析了、
版本号符合预期、日志无错误；然后**实测原生窗口标题**、并从 PE 里把图标读回来。
只有这些都过了，提升到 `dist/` 才是一条 `cp`。

v0.4 实测：**热启动 1.6 秒**（跑了两遍）。同一台机器上 v0.3 量到 1.3 秒，
而这 0.3 秒的差**是噪声不是退化** —— 载荷只大了 1.9 KB。
这点时间也几乎全是单文件包在解压自己；刚拷贝过来的第一次运行是 5.3 秒，
因为 Defender 要扫一个没见过的文件。所以这个数字值得跑两遍再信。

## 说明与限制

* 图标源自一张**不在本仓库里**的照片。`assets/make_icon.py` 可以用任意图片重新生成 `app.ico`。
* 实际上是 Windows 专用：mod 发现、图标与版本资源都是 Windows 特有的。
  二进制格式那一层没有 Windows 依赖。
* 构建产物**未签名**，首次运行会有 SmartScreen 警告。
* PvP / 遭遇战牌组是刻意不碰的。
* 与 Eugen Systems 无关。WARNO 及其文件格式归他们所有。
